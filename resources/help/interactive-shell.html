Interactive Shell Tutorial

Use Python and ASE to inspect, edit, and relax the structures in your viewport. This guide starts with an already loaded STRUCT_0. Each code block is an example to copy into the shell editor and run; explanatory text is not Python code.

Quick start: load a structure, open Code → Open Interactive Shell, enter print(STRUCT_0), and click Run.

1. Open the shell and run code

  1. Load a structure using Files → Import Structures, or drop its file onto the viewport.
  2. Expand Code and click Open Interactive Shell. You can move this separate window beside the viewport.
  3. Check the structure list at the top of the shell. It shows each Python variable, source filename, atom count, and which structure is visible.
  4. Enter the following code in the editor and click Run, or press Command+Enter on macOS / Ctrl+Enter on Windows and Linux.
print(STRUCT_0)
print("Atoms:", len(STRUCT_0))
print("Formula:", STRUCT_0.get_chemical_formula())

Run executes the entire editor, including any previously inserted examples. Replace the editor contents when you want to run a different standalone example. Use print(...) to see values in Output; a bare expression does not automatically display its result. Indent Python blocks consistently; Tab inserts four spaces.

The Insert example… menu appends a sample to the editor. Clear output clears displayed text without changing the code, structures, or Python variables.

2. Understand STRUCT_N and the Python session

Each loaded document has an ordinary ASE Atoms object named STRUCT_N, where N is its stable session ID. For example, STRUCT_0 and STRUCT_1 refer to separate documents. Switching the viewport does not rename them. Always use the variable shown in the structure list.

atoms = STRUCT_0
studio.show(atoms)
print(atoms.positions)

atoms = STRUCT_0 creates an alias: edits through either name affect the same object. STRUCT_0.copy() creates an independent object; use studio.add to give that copy its own document and viewport representation.

Python variables, imports, functions, and attached calculators persist between runs. Closing the shell window hides it; reopening keeps your editor and session. Quitting the application ends the session. Save scripts and structures you need to keep.

Imports and native geometry edits synchronize into the shell while it is idle. During execution, conflicting geometry editing controls are disabled. Camera and appearance controls remain available. The np, ase, Atoms, and studio names are provided when a session starts.

3. Inspect and edit a loaded structure

ASE positions and cell lengths use ångströms. Arrays use zero-based atom indices, so atom 0 is the first atom.

atoms = STRUCT_0
print("First five positions:", atoms.positions[:5])
print("Cell:", atoms.cell)
print("Periodic directions:", atoms.pbc)

# Translate every atom by 0.2 Å along z.
atoms.positions[:, 2] += 0.2

A successful run automatically publishes changed registered structures to the app. Running this block again translates the atoms another 0.2 Å. Geometry updates preserve the camera view rather than refitting it each time.

You can also use ASE methods such as atoms.rotate(10, "z") or atoms.set_cell(...). ASE constraints are supported; methods such as set_positions can respect constraints, while direct writes to the positions array bypass them.

To replace a registered object with a sliced, reordered, or repeated version, assign it back to its STRUCT_N name. For example:

# Keep all atoms, in reverse order.
STRUCT_0 = STRUCT_0[::-1]

After rebinding STRUCT_0, assign atoms = STRUCT_0 again if you need that alias. Existing aliases still refer to the previous Python object.

4. Show intermediate changes in the viewport

For loops and simulations, call studio.update(atoms) to publish intermediate geometry. It does not calculate forces or energy. Select the document with studio.show(atoms) when you want to watch it.

from time import sleep

atoms = STRUCT_0
studio.show(atoms)
for step in range(20):
    atoms.positions[:, 2] += 0.02
    studio.update(atoms)
    sleep(0.1)

This moves the structure a total of 0.4 Å along z. The short pause makes the motion easy to observe. Live updates/s sets the maximum preview rate from 1 to 30; set it before running. Rendering speed can limit the actual rate, and intermediate steps may be skipped. The final successful state is still applied.

Updating a structure that is not visible keeps its geometry current without switching the viewport. Image capture briefly defers updates. Ray tracing restarts its accumulation when geometry changes and settles again after the run finishes.

5. Relax STRUCT_0 with live visualization

Relaxation requires an ASE calculator that supplies forces for your material. The following example reuses an attached calculator; if none exists, it uses ASE's EMT calculator. EMT is suitable for a quick copper demonstration, but is not a general-purpose model for every element or material. Replace it with an appropriate calculator for your scientific calculation.

This example changes the loaded STRUCT_0 directly. It relaxes atom positions while keeping the unit cell fixed and respecting existing ASE constraints.

from time import sleep
from ase.calculators.emt import EMT
from ase.optimize import BFGS

atoms = STRUCT_0
studio.show(atoms)
if atoms.calc is None:
    atoms.calc = EMT()  # Choose a calculator for your material.

def update_view():
    studio.update(atoms)
    sleep(0.15)  # Optional: make intermediate motion visible.

optimizer = BFGS(atoms, logfile="-")
optimizer.attach(update_view, interval=1)
converged = optimizer.run(fmax=0.05, steps=100)

print("Converged:", converged)
print(f"Final energy: {atoms.get_potential_energy():.6f} eV")

fmax=0.05 requests a maximum force below 0.05 eV/Å; steps=100 limits the optimization steps. Reaching that limit does not guarantee convergence: check the printed result and final fmax in Output. logfile="-" sends the optimizer log to Output.

For full speed, remove sleep(0.15), or attach the update helper directly:

optimizer.attach(studio.update, interval=1, atoms=atoms)

Use this attachment instead of the update_view attachment. If the input is already relaxed, the optimizer may finish immediately with little visible motion. Try the separate Live relaxation demo from the example menu to visualize a deliberately displaced copper crystal.

6. Create structures and work on copies

studio.add(atoms) creates a new document, prints its assigned STRUCT_N name, and returns the registered object. The supplied geometry is used directly, without applying sidebar replication a second time.

# Experiment on a separate copy of a loaded structure.
trial = studio.add(STRUCT_0.copy())
studio.show(trial)
trial.positions[:, 2] += 0.5

ASE copies do not carry an attached calculator. Attach a calculator to the copy before evaluating energy or forces. Creating a new structure with ASE also works:

from ase.build import bulk

copper = studio.add(bulk("Cu", cubic=True) * (2, 2, 2))
studio.show(copper)

Each run of these examples adds another document. A Python variable alone does not add a document: register newly created objects before calling studio.update or studio.show.

7. The studio helper reference

HelperPurpose
studio.update(atoms)Publish a registered object's geometry during a run. No calculator evaluation.
studio.show(atoms)Select its document in the viewport. Does not reset camera scale.
studio.add(atoms)Create a document and return its registered ASE object.
studio.original(N)Return an independent copy of document N's original input.

The original input is immutable. For a separate view of the original of document 0:

original_copy = studio.add(studio.original(0))
studio.show(original_copy)

The original is the input before working edits and sidebar replication. Use studio.original(0) to access it in Python; the app's internal STRUCT_0_RAW / STRUCT_0_CURRENT labels are not shell variables.

8. Scripts, files, and the Python environment

Save .py saves the editor contents. Open .py appends a file's code to the editor so existing text is retained; review the combined script before running.

Select Working directory… before a run. Relative file paths, optimizer logs, and calculator output use that folder unless your script changes directory.

from ase.io import write

# Writes into the selected working directory.
write("relaxed.xyz", STRUCT_0)

You can also export the displayed working structure with Files → Export Structures. Native exports preserve geometry and position precision; they are not complete Python session checkpoints. Save your script separately.

The shell uses ATOM-STUDIO's bundled Python, ASE, and NumPy. Packages in your system Python or Conda environment are not automatically available. Additional packages and external calculation engines are not installed by the shell; the application runtime remains read-only. An ASE interface to an external engine still needs that engine and its configuration.

Enter Python code, not terminal commands. input() is unavailable; set parameters in the editor. The embedded session does not supply a standalone interpreter for multiprocessing spawn or Python subprocess commands launched through sys.executable.

9. Stop, errors, restart, and restoring geometry

  • Stop: requests an interruption. If code cannot stop promptly, Python is restarted after two seconds. The viewport retains the last accepted geometry.
  • Errors: read the last lines of the traceback in Output. The app retains the last published geometry; Python edits made before an error can remain in memory even if they were not published. Correct them and run again, or restart.
  • Restart Python: clears Python variables, imports, functions, and calculators, then reloads the current document geometry. It retains the editor text and does not undo published geometry changes.
  • Reset to Original: use this under Structure while the shell is idle to restore the active document's original input with the current global replication factors. This replaces its working edits.

Changing sidebar replication factors also rebuilds periodic working structures from their originals, replacing Python edits. Use a separate document for experiments you want to compare. Published edits are not automatically saved to the imported source file.

10. Troubleshooting and practical limits

“STRUCT_0 is not defined”

Import a structure and check the shell's structure list. Use the displayed STRUCT_N name; IDs are stable and need not be consecutive.

No motion appears during a calculation

Select the right document with studio.show. Call studio.update inside the loop or attach it to the optimizer. Without intermediate updates, changes appear after successful completion. A fast run, small displacements, or an already relaxed structure can also produce little visible motion.

“Atoms object has no calculator” or an unsupported element error

Attach a suitable calculator before asking for energy or forces. Imported geometry does not automatically acquire a computational model. EMT supports only a limited set of elements; choose another calculator when necessary.

“Use the Atoms object named STRUCT_N”

You passed an unregistered object or an outdated alias. Use the current STRUCT_N object, or register an independent copy with studio.add.

Updates fail after changing arrays or metadata

Positions and cell entries must be finite; array lengths must match the atom count. ASE metadata and constraints must be serializable. Read the traceback, correct the object, and rerun. Restart restores Python's objects from the last accepted document geometry.

What is preserved during conversion?

Snapshots retain double-precision positions, serializable ASE constraints, custom arrays, and typed metadata. Rendering uses float coordinates. Existing atom identities preserve selection and appearance through slicing and reordering; new atoms receive default appearance. Explicitly deleted bonds remain deleted through live connectivity updates until the working structure is reset.

Large structures and expensive calculators take longer to compute, transfer, and render. Preview updates are bounded, and Output omits excessive text. Start with a small system and a modest update rate when checking a new script.
